## 1. 배경 — 지금 무엇이 문제인가

교시(회차) 정보가 **DB에 없고 프런트 3곳에 복제된 상수**로 존재합니다.

| 위치 | 내용 |
|---|---|
| [reservation.js:18](../src/main/resources/static/js/reservation/reservation.js#L18) | `1~4교시 / 10:00~13:50` 고정 배열 |
| [monitor-live.js:55](../src/main/resources/static/js/monitor/monitor-live.js#L55) | 동일 배열 + `ALL` 항목 |
| [diary.js:9](../src/main/resources/static/js/growth/diary.js#L9) | 동일 배열 |

세 파일 모두 주석에 "교시 마스터 데이터가 아직 없어 고정 목록으로 둔다"라고 적혀 있고,
"교시당 50분 수업 + 10분 휴식, 2026-08-07 확정"이 명시돼 있습니다.

여기서 생기는 문제는 세 가지입니다.

1. **센터마다 운영시간이 다른데 반영할 수 없습니다.** 시안은 13:00~19:00인데 코드는 10:00~13:50입니다.
2. **정원 개념이 아예 없습니다.** [ReservationService:26](../src/main/java/com/hohoedu/book_clinic/reservation/ReservationService.java#L26)은
   같은 학생의 중복 예약만 막고, 한 교시에 몇 명까지 받을지는 검증하지 않습니다. 무제한으로 들어갑니다.
3. **휴일/단축운영을 표현할 방법이 없습니다.** 광복절에도 예약 화면은 4교시를 정상 노출합니다.

이 화면은 위 셋을 **DB 마스터 데이터로 옮겨서** 센터 직원이 직접 관리하게 하는 것이 목적입니다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| **요일 스케줄** | 센터의 요일별 기본 운영 규칙. 월~일 7개가 항상 존재하며, 휴무 요일도 행은 유지 |

| **예외일** | 요일 스케줄과 다르게 운영하는 특정 날짜. 휴무 / 운영시간 변경 / 회차 변경 3가지 형태 |
| **마감** | 해당 회차의 신규 예약만 차단. 이미 잡힌 예약은 유지 **[가정]** |

## 3. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-01 | 월~일 7개 버튼을 노출하고, 각 버튼에 현재 설정된 **운영/휴무** 상태를 함께 표시한다 |
| FR-02 | 요일을 선택하면 하단 영역(요일 스케줄 + 회차 관리)이 그 요일 기준으로 전환된다 |
| FR-03 | 저장은 **현재 선택된 요일 1개만** 대상으로 한다 **[가정]** |

### 3-2. 요일 스케줄 (운영시간 · 기본값)

| ID | 요구사항 |
|---|---|
| FR-05 | 운영 시작/종료 시각을 설정한다 |
| FR-06 | 회차 기본 시간(분)을 선택한다. 선택지는 30/40/50/60분 **[가정]** |
| FR-07 | 최대 예약 인원 기본값을 `-`/`+` 및 직접 입력으로 설정한다 |
| FR-08 | FR-05~07은 **회차 자동 생성의 입력값**이며, 실제 예약 판정은 개별 회차 값을 따른다 |
| FR-09 | **회차 자동 생성**은 운영시간을 `회차 기본 시간 + 휴식 10분` 단위로 잘라 회차 목록을 채운다 **[가정: 휴식 10분 고정]** |
| FR-10 | 자동 생성 시 기존 회차 목록은 전량 대체된다. 예약이 존재하면 경고한다 **[가정]** |
| FR-11 | 요일을 휴무로 전환해도 기존 회차 설정은 삭제하지 않고 보존한다 |

| ID | 요구사항 |

| FR-14 | 회차를 개별 삭제한다 |
| FR-15 | 회차 시간대는 서로 겹칠 수 없다. 저장 시 서버에서 검증한다 **[가정 — 시안은 4개 회차가 모두 13:00~13:50으로 동일함]** |

### 3-4. 특정일 예외 설정

| ID | 요구사항 |
|---|---|
| FR-18 | 날짜를 선택하고 예외 유형을 지정한다: 휴무 / 운영시간 변경 / 운영회차 변경 |
| FR-19 | 세 유형은 **복수 선택 가능**하되, 휴무 선택 시 나머지는 무시한다 **[가정]** |
| FR-20 | 변경 사유를 100자 이내로 입력한다 |
| FR-21 | 운영회차 변경 시, 해당 날짜의 회차 목록과 **각 회차의 현재 예약 인원**을 보여주고 회차별 마감 처리를 한다 |
| FR-22 | 등록된 예외 일정을 날짜순으로 목록 노출하고 개별 삭제한다 |
| FR-23 | 같은 날짜에 예외는 1건만 존재한다. 재등록 시 덮어쓴다 |
| FR-24 | 과거 날짜에는 예외를 등록할 수 없다 **[가정]** |

### 3-5. 예약 판정 규칙 (다른 화면이 이 설정을 읽는 방식)

특정 날짜의 예약 가능 회차는 다음 순서로 결정합니다.

```
1. 그 날짜에 예외가 있고 휴무면        → 예약 불가, 종료
2. 없으면 해당 요일의 요일 스케줄을 사용
   (요일이 휴무면 예약 불가, 종료)
3. 예외에 운영시간이 지정돼 있으면      → 운영시간 덮어쓰기
4. 예외에 회차별 변경이 있으면          → 해당 회차만 마감 또는 정원 교체
5. 남은 회차 각각에 대해 예약 건수 < 정원이면 예약 가능
```

## 4. 다른 화면에 미치는 영향

이 화면은 신규 개발이지만, **기존 3개 화면의 수정이 반드시 동반**됩니다.

| 대상 | 필요한 변경 | 난이도 |
|---|---|---|
| 예약 등록 | `TIME_SLOTS` 상수 제거 → 날짜 선택 시 서버에서 회차 목록 조회. 정원 초과 검증 신규 추가 | 상 |
| 실시간 모니터링 | `TIME_SLOTS` 상수 제거 → 회차 탭을 동적 생성. 회차 수가 4개 고정이 아니게 됨 | 중 |
| 독서일지 | `TIME_SLOTS` 상수 제거. **과거 일지의 교시 라벨**을 어떻게 표시할지 결정 필요(6장 참조) | 중 |

`erp_bookstore_clinic_reservation.time_slot`과 `erp_bookstore_diary.record_time`이
`'1'`~`'4'` 문자열이므로, 회차 번호를 그대로 유지하면 기존 데이터 마이그레이션은 불필요합니다.

## 5. 데이터 요구사항

[ddl-schedule.sql](../src/main/resources/db/ddl-schedule.sql)에 초안이 있습니다.

| 테이블 | 단위 | 대응 요구사항 |
|---|---|---|
| `erp_bookstore_schedule_day` | 센터 × 요일 | FR-01, FR-05~07, FR-11 |
| `erp_bookstore_schedule_slot` | 요일 × 회차 | FR-12~14 |
| `erp_bookstore_schedule_exception` | 센터 × 날짜 | FR-18~20, FR-22~23 |
| `erp_bookstore_schedule_exception_slot` | 예외 × 회차 | FR-21 |

예외 유형(휴무/시간변경/회차변경)은 별도 코드 컬럼 없이
`is_closed` · 시간 컬럼 NULL 여부 · 하위 테이블 행 존재로 파생시킵니다.

### 초기 데이터

기존 하드코딩값(1~4교시 10:00~13:50, 50분+휴식 10분)을 전 센터에 시드로 넣어야
예약·모니터링 화면이 전환 직후에도 동일하게 동작합니다. **[가정]**

## 6. 미확정 항목 — 확정 전에는 착수 곤란

| # | 항목 | 왜 중요한가 | 잠정 가정 |
|---|---|---|---|
| 1 | **과거 스케줄 소급 변경 허용 여부** | 운영시간을 바꾸면 지난 독서일지의 "3교시"가 새 시간으로 보인다. 이력 보존이 필요하면 `effective_from` 구조가 추가돼 테이블 설계가 달라진다 | 소급 변경 허용(이력 미보존) |
| 2 | **회차 = 시간대 vs 반(class)** | 시안의 4개 회차가 전부 13:00~13:50이다. 같은 시간에 여러 반이 도는 구조라면 예약·모니터링의 교시 개념이 통째로 바뀐다 | 시간대(목업 미완성으로 간주) |
| 3 | **센터 범위** | 화면에 센터 선택이 없다. 본사가 전 지점을 설정하는지, 로그인 센터만인지에 따라 권한·조회 구조가 다르다 | 로그인 센터 기준 |
| 4 | **예약 존재 시 휴무/마감 처리** | 시안의 "1회차 - 예약인원 3명 [마감 처리]"가 정확히 이 상황. 기존 예약 자동취소 / 유지 / 학부모 통보 중 무엇인가 | 유지, 신규만 차단 |
| 5 | **회차 간 휴식시간** | 자동 생성이 13:00~19:00을 채우려면 휴식값이 필요한데 시안에 입력란이 없다 | 10분 고정 |
| 6 | **요일별 회차 수 가변 여부** | 13:00~19:00 / 50분이면 6~7회차가 나오는데 시안엔 4개뿐. 가변이면 프런트 3곳을 전부 동적으로 바꿔야 한다 | 가변 |
| 7 | **시안 시간(13:00~19:00) vs 코드(10:00~13:50)** | 2026-08-07 확정 주석과 다르다. 어느 쪽이 실제 운영값인가 | 시안이 예시값, 실제는 센터별 설정 |
| 8 | **저장/복사 버튼 범위** | 요일 1개 저장인지 7개 일괄인지, 복사 방향이 어느 쪽인지 | 요일 1개 저장 / 현재→타 요일 복사 |

1·2·3번은 답에 따라 **테이블 구조 자체**가 바뀝니다.
