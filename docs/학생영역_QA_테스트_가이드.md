# 학생 영역 QA 테스트 가이드

- 작성일: 2026-08-25

---

## 1. 사전 준비

### 1.1 테스트 계정

| 구분 | 아이디 | 비고 | 용도 |
|---|---|---|---|
| 학생 | 88980 | 1학년 | 정상 플로우 |
| 학생 | 88981 | 1학년 | 정상 플로우 |
| 학생 | 88982 | 1학년 | 정상 플로우 |
| 학생 | 88983 | 2학년 | 정상 플로우 |
| 학생 | 88984 | 2학년 | 정상 플로우 |
| 학생 | 88985 | 3학년 | 예외 케이스 전용 — **오늘 예약 없음** 상태로 세팅 |
| 학생 | 88986 | 3학년 | 예외 케이스 전용 — **이용권 잔여 0** 상태로 세팅 |
| 관리자 | clinic01 | 비밀번호 0000 | |

### 1.2 사전 확인 사항
- 테스트할 학생의 **오늘 예약**이 등록되어 있는지, **이용권(pass) 잔여**가 있는지 확인 (둘 다 없으면 로그인 단계에서 막힘)
- 테스트 학생의 기존 학습 이력(추천 이력/완독 이력/뱃지)이 남아있으면 케이스가 꼬일 수 있으므로, 필요 시 관리자 화면에서 초기화 후 시작

---

## 2. 전체 플로우 개요

```
로그인
  → 메인: 레벨/뱃지/추천도서 표시, 입실 처리
  → 책 추천 확정: 미해결 추천 재사용 or 신규 선정
  → 문제풀이 진입: 기본(qlevel 01) / 심화(qlevel 02)
  → 제출: 서버 채점
  → 결과: 합격/불합격, 뱃지 지급
  → (합격 시) 완독 처리 + 레벨 재계산
  → 반납/퇴실(관리자 강제퇴실 포함)
```

---

## 3. 단계별 테스트 절차

### 3.1 로그인
1. 학생 로그인 화면에서 유효한 app_id 입력
2. **정상 케이스**: 오늘 예약 있음 + 이용권 잔여 있음 → 로그인 성공, 메인으로 이동
3. **예외 케이스**
   - `88985`(오늘 예약 없음) 로그인 → 거부/안내 메시지 확인
   - `88986`(이용권 잔여 0) 로그인 → 거부/안내 메시지 확인
   - 정상 계정(예: `88980`)으로 **다른 센터 소속 기기(키오스크)**에서 로그인 시도 → 센터 불일치로 거부되는지 확인
   - 존재하지 않는 app_id(예: `00000`) 로그인 → 명확한 에러 안내

### 3.2 메인 화면
1. 진입 시 표시되는 정보 확인: 현재 레벨/진행률, 뱃지(카드 컬렉션), 오늘의 추천 도서
2. **입실 처리 시점 확인**: 로그인 직후가 아니라 이 화면에서 추천이 확정되는 순간 입실 처리됨 → 관리자 모니터링 화면에서 실제로 "입실" 상태로 전환되는지 동시에 확인
3. 새로고침/재진입 시 **같은 추천 도서가 유지**되는지 확인 (멱등성 — 매번 다른 책이 뜨면 버그)
4. 결과 확인 화면(result)에서 돌아왔을 때 `markResultViewing` 상태가 정리되는지(모니터링 화면 기준) 확인

### 3.3 책 추천/대여
1. 미완료(미해결) 추천이 있는 상태에서 재진입 → 새 책이 아니라 **기존 추천이 그대로 유지**되는지 확인
2. 추천 가능한 책 풀이 소진된 극단적 케이스에서 폴백 로직 동작 확인(가능하면 테스트 데이터로 재현)
3. 동일 학생으로 짧은 시간 내 **동시 요청(더블클릭/새로고침 연타)** 을 보내 중복 대여가 발생하지 않는지 확인

### 3.4 문제풀이 진입
1. 기본 문제(qlevel=01)와 심화 문제(qlevel=02) 각각 진입해서 문제/보기가 정상 노출되는지 확인
2. 진입 시 관리자 모니터링 화면에 "문제풀이 시작" 상태가 반영되는지 확인 (`markQuizStarted`)
3. 비로그인 상태로 문제 데이터/정답이 노출되지 않는지 확인 (네트워크 탭에서 응답에 정답(ans)이 포함되는지 점검)

### 3.5 제출/채점
1. **정답 위주 제출**: qlevel=01에서 정답률 2/3 이상 → "합격" 처리, 완독/레벨 반영되는지 확인
2. **오답 위주 제출**: 정답률 2/3 미만 → "재도전" 안내, 완독 처리 안 됨 확인
3. **심화(qlevel=02) 제출**: 완독/레벨에 영향 없이 기록만 남는지 확인
4. **위조 테스트**: Postman 등으로 클라이언트 정답 수를 조작해서 보내도 서버가 실제 정답과 대조해 채점하는지 확인 (클라이언트 신뢰 여부 검증)
5. **타 학생 위장 테스트**: 세션의 studentId와 다른 studentId를 요청 본문에 넣어 제출 → 거부되는지 확인 (`requireOwnStudent`)
6. **재제출**: 이미 완독 처리된 문제를 다시 제출했을 때 응답이 모순되지 않는지 확인 (기존 버그리포트 10번 재검증 대상)

### 3.6 결과 화면
1. 합격/불합격에 따른 화면 문구·다음 액션 버튼이 올바른지 확인
2. **뱃지 지급 확인**
   - 기본 뱃지(첫 시도 기준) 정상 지급 여부
   - 심화 뱃지 지급 조건 확인
   - 책별 뱃지(카드) 지급 및 10장 수집 시 진행도 표시 확인
   - **0점 제출에도 뱃지가 지급되는지** 별도 확인 (기존 버그리포트 11번, 미해결로 표시되어 있었음 — 현재 상태 재검증 필요)
3. sessionStorage로 결과가 전달되는 구조이므로, 결과 화면을 새로고침했을 때 데이터가 유실되지 않는지/에러 없이 처리되는지 확인

### 3.7 반납/퇴실
1. 학생 메인 화면의 "퇴실하기" 버튼으로 정상 퇴실 처리 확인
2. 관리자 강제 퇴실(모니터링 화면)로도 처리되는지, 인증 없이 임의 학생을 퇴실시킬 수 있는지(권한 체크) 확인 — 기존 버그리포트 4번은 "보류" 결정된 항목이므로 현재 정책과 일치하는지만 확인
3. 퇴실 후 **같은 예약으로 재입실이 무제한 가능한지** 확인 (기존 버그리포트 8번, 미해결 상태였음 — 현재 재현 여부 확인)
