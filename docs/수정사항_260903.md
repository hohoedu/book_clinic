## P0-1. ② 심화 미응시 상태에서 입실하면 다음 책이 추천되는 버그

**원인**: 심화 게이트는 개인 폰 앱 경로에만 걸려 있다.
- `ClinicController.java:71` → `recommendBook(studentId, true)` — 게이트 적용
- `StudentViewController.java:407` (`POST /attendance/enter`) → `recommendBook(studentId)` — **게이트 미적용**

출석체크 키오스크에는 "책 추천받기" 버튼 플로우가 없어서 `입실 = 책이 무조건 나온다`로 설계돼 있던 것(주석 `StudentViewController.java:382-391`). 그래서 심화를 안 푼 학생도 입실만 하면 다음 책이 추천·대여까지 확정된다.

**수정 (로직)**
1. `/attendance/enter`는 **입실 처리 + 읽던 책(PENDING) 확인까지만** 하고, 새 추천은 하지 않는다.
   - `recommendBook` 대신 "PENDING 있으면 그 책 / 없으면 없음" 경로로 분리 (`getHomeState` 계열 재사용 검토).
   - PENDING이 없으면 `book-confirm.html`에 "책 추천" 버튼(P1-2)을 띄운다.
2. 그 버튼에서 추천을 부를 때는 `enforceAdvancedGate = true`로 호출 → 심화 미응시면 `Exception400("심화 문제를 먼저 풀어야…")`가 그대로 안내 카드로 뜬다.
3. 게이트 판정 자체(`advancedGateBlocks`, `ClinicService.java:353`)는 그대로 둔다. 단 "직전 완독일이 오늘이 아니면 통과" 규칙이 유지되는지 재확인 필요.

**영향 파일**: `StudentViewController.java`, `ClinicService.java`, `templates/student/book-confirm.html`

이름만 다르고 동작은 둘 다 **로그아웃**이다. 기존 로그아웃 핸들러(`student-result.js:50-65` — `POST /student/logout` → 저장소 비우기 → `/student`)를 그대로 재사용하고 **라벨과 색만 다르게** 준다. 새 화면·새 API가 필요 없다 → 구현 부담이 거의 없다.

| 버튼 | 라벨 | 색 | 동작 |
|---|---|---|---|
| 불합격 | 다시 읽으러 가기 | 빨강 | 로그아웃 |
| 심화 완료(오답 0) / 심화왕 | 여권 쓰러 가기 | 기본 | 로그아웃 |

**핵심 변경 2가지**
1. **⑨ 불합격은 문제 재도전 버튼을 없앤다.** `renderRetryResult`에서 `retryBtn`(→ `/student/question`)을 숨기고 로그아웃 동작의 빨간 버튼 하나만 남긴다. (책은 아직 PENDING이라 다시 와서 이어 읽으면 된다.)
2. **심화·여권 버튼은 "오답 0"이 게이트다.** 지금은 심화 버튼이 오답 유무와 무관하게 항상 열려 있다(`student-result.js:224-232`) → `result.wrongQnums`가 비었을 때만 노출하도록 조건 반전. 심화왕에서 기본 오답이 남아도 틀린문제 버튼을 띄우던 예외(`student-result.js:196-206`)는 삭제하고 여권 버튼 단독으로 통일.

## P1-1. ① 책 홀딩(자물쇠) — 다 못 읽은 책 이어 읽기 (설계 확정 2026-09-03)

**규칙**
- 자물쇠는 **선생님이 모니터링 화면에서** 누른다. 입력값은 **읽은 페이지 수** 하나.
- 홀딩은 책을 잠그는 게 아니다. 홀딩된 책도 **재고만 있으면 다른 학생 누구에게나** 추천된다(요일·회차 무관).
- 홀딩한 학생이 **언제 오든**(요일·회차 상관없이) 그 책이 **최우선으로 다시 배정**된다 = 이어 읽기.

**이미 되고 있는 것 — 새로 만들 필요 없음**
1. 퇴실 시 실물은 **이미 반납된다** (`MonitorService.java:115`, `returnActiveLoanByStudent`) → 그동안 남이 빌릴 수 있다
2. 추천 쿼리는 **남은 재고 수량만** 본다 (`ClinicMapper.xml:75`, `i.qty - i.loaned_qty - i.lost_qty > 0`) — 예약/회차 조건 없음
3. 미완료(PENDING) 추천이 있으면 **무조건 그 책이 먼저 나온다** (`ClinicService.java:384`)
4. 다시 오면 `ensureActiveLoan`이 **재대여**한다 (`ClinicService.java:815`)

→ "언제 오든 이어 읽기 + 그 책은 남도 빌릴 수 있음"은 현행 동작 그대로다. **요일·회차 컬럼은 불필요**하다.

**그래서 실제로 만들 것은 2개**
1. **읽은 페이지 기록** — 자물쇠 버튼의 실질 기능. `recommend_log.hold_page`
2. **`PENDING → HOLD` 상태 분리** — 기능이 아니라 **가시성**. 지금은 "오늘 읽는 중"과 "다 못 읽고 넘어간 책"이 똑같이 PENDING이라 모니터링에서 구분이 안 된다. 퇴실 시 미완료 추천을 HOLD로 내리고, 다시 그 책을 받을 때 PENDING으로 올린다.
   자물쇠를 눌렀든 안 눌렀든 **전환은 동일**하고, 차이는 `hold_page`가 채워졌는지뿐이다.

**DB**
```sql
ALTER TABLE erp_bookstore_recommend_log ADD
    hold_page  INT         NULL,              -- 홀딩 시점까지 읽은 페이지 (자물쇠로 입력)
    hold_use   VARCHAR(1)  NULL DEFAULT 'Y';  -- 홀딩 유효 여부. 폐기는 논리삭제 'N' (is_active 관례와 동일)
```
`status`에 값 추가: `PENDING / DONE / **HOLD**`

**동작 순서**
- 퇴실: 미완료 추천 `PENDING → HOLD` (실물 반납은 현행 그대로)
- 재입실/추천: `hold_use='Y'`인 HOLD가 있으면 **최우선** → `HOLD → PENDING` 승격 + 재대여 + "○○쪽부터 이어 읽어요" 안내
- 문제 제출로 완독: `PENDING → DONE` (폐기가 아니라 소진)
- 또 못 읽고 퇴실: 같은 행의 `hold_page` **갱신** (새 행 아님)

**재고가 없을 때 (확정)**
대여는 **입실~퇴실 사이에만** 존재하므로 며칠이 지나든 재고는 항상 돌아온다. 재고가 0인 경우는 딱 하나 — **1권짜리 책을 같은 회차의 다른 학생이 먼저 배정받은 순간**뿐이다.
이때는 **A에게 다음 책을 추천**하고, 그 순간 **이전 홀딩은 폐기**한다(아래 규칙). 모니터링에는 재고 없음을 알린다.

**유효 홀딩은 학생당 최대 1건 — 다음 책을 받으면 이전 홀딩 폐기 (확정 2026-09-03)**
어떤 이유로든 A가 **다음 책을 받는 순간** 이전 홀딩은 `hold_use='N'`으로 폐기한다.

*이유*: 2주 뒤에 그 책을 다시 펴봐야 앞부분 내용이 기억나지 않는다. 비교적 최근에 읽던 책을 이어서 완독하는 게 맞고, 폐기된 책은 **나중에 새로 추천받아 처음부터** 읽는 편이 낫다.

*따라서 재추천 방지 쿼리를 손봐야 한다.* 지금은 `recommend_log`에 행이 있으면 그 책을 그 학생에게 다시 추천하지 않는다(`ClinicMapper.xml:76`의 `NOT EXISTS`). 폐기된 홀딩(`status='HOLD' AND hold_use='N'`)은 **완독한 적이 없는 책**이므로 이 판정에서 **제외**해서 후보로 되살려야 한다. 다시 추천되면 새 행으로 시작하고 `hold_page`는 비운다(처음부터 읽기).

*주의*: 제외하는 순간 그 책이 곧바로 다음 후보로 다시 올라올 수 있다. 직전 분류·장르를 피하는 dedup 규칙(`pickWithFallback`)이 어느 정도 걸러주지만 완전하지는 않다. "방금 폐기한 책이 바로 또 나오는" 상황이 보이면 최근 N일 제외 조건을 덧붙인다.

**폐기 (`hold_use='N'`) — 4가지**
1. **A가 다음 책을 받음** (위 규칙 — 가장 흔한 경로)
2. 선생님이 자물쇠를 다시 눌러 홀딩 해제 (오조작 취소 / 그 책을 그만 읽기로 함)
3. 모니터링에서 그 책을 다른 책으로 교체 (`.book-swap-btn` 대상을 HOLD까지 열 경우)
4. 실물이 분실·훼손 폐기되어 **그 책의 재고 자체가 사라짐**

**영향 파일**: 패치 SQL 신규 + `ddl-core.sql`, `ClinicRepository`/`ClinicService`(HOLD 승격 분기), `MonitorService`(퇴실 시 HOLD 전환), `monitor-live.js/css`(자물쇠 버튼 — 교체 버튼 `.book-swap-btn`, `monitor-live.js:542` 옆)
