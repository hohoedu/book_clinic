# 운영 스케줄 서버 구현 계획

- 작성일: 2026-08-14
- 화면: `templates/operation/operation-schedule.html` (완료, 프론트 목업 — 서버 미연동)
- DB: `src/main/resources/db/ddl-schedule.sql` 설계, `schema.sql`에 반영 + 로컬 DB 11개 테이블 생성 완료
- 참고: 화면 CRUD 전체 목록은 별도 정리(claude.ai Artifact "운영 스케줄 기능 명세")

## 결정된 사항 4가지

1. 적용 시작일 + 즉시 적용 체크박스 → 저장 버튼 앞 배치 (화면 반영 완료)
2. 예외 일정 **수정 화면 없음** — 삭제 후 재등록으로 대체
3. 센터는 **로그인 직원 센터로 고정**, 센터 선택 UI 없음
4. 예약 걸린 슬롯 저장/삭제 시 **경고 + 차단** — 서버 API 붙일 때 반드시 같이 구현 (아직 미착수)

## 구현 순서 (범위 축소 없음, 8/14~8/17 3일 배정)

1. **요일별 스케줄 조회 API** — 센터 기준 요일별 최신 버전 조회 → 요일 탭 로드
2. **요일별 스케줄 저장 API** — 운영여부·운영시간·회차기본시간·최대예약인원 + 회차 목록을 적용 시작일(effective_from) 기준 upsert
   - ✅ **8/14 완료.** `schedule` 패키지(Controller/Service/Repository/dto) + `mapper/ScheduleMapper.xml` 신규.
     `GET|POST /admin/operation/schedule/week`. 센터는 로그인 유저 고정. 같은 effective_from 재저장 시
     `_del`에 UPDATE 스냅샷 남기고 덮어씀. seq는 서버가 시작시각 순으로 재부여. 예약 있는 요일은 저장
     자체를 차단(결정 4 일부 선반영).
3. **materialize() 슬롯 생성 엔진** — 요일 버전 + 예외를 합쳐 `slot_instance`를 찍어내는 핵심 로직.
   - ✅ **8/18 완료.** `ScheduleMaterializer` + `SlotInstanceRepository` / `mapper/SlotInstanceMapper.xml` 신규.
     진입점 3개: `materializeHorizon`(오늘~오픈일 전체, 배치용) / `materializeRange`(예외 등록·삭제용) /
     `materializeDayOfWeek`(요일 저장 직후). 기간 입력을 한 번에 읽어 날짜별로 규칙을 고르고,
     잉여 슬롯 DELETE + MERGE upsert로 `slot_instance_id`를 보존한다. 예약(RESERVED)이 걸린 날짜는
     건너뛰고 `blockedDates`로 반환. `saveWeek`에 연동 완료.
   - **예약 오픈 기간은 `RESERVATION_OPEN_DAYS = 28`(4주)로 잡았다** — 기획에 정해진 값이 없어
     임의로 둔 것이므로 확정되면 상수만 바꾸면 된다.
4. **예약 보호(경고·차단)** — 결정 4. 슬롯에 예약이 있으면 저장·삭제 자체를 막는다.
   - ✅ **8/18 완료.** 요일 저장(8/14) + 예외 등록·삭제 양쪽에 적용. 엔진도 예약 걸린 날짜는 건너뛴다(3중).
5. **예외 일정 조회·등록 API** — 기간 겹침 검증 포함, 등록 즉시 3번 엔진 재호출
   - ✅ **8/18 완료.** `ScheduleExceptionService` + `ScheduleExceptionRepository` / `ScheduleExceptionMapper.xml`.
     `GET|POST /admin/operation/schedule/exception`. 겹침 규칙은 ddl 주석 그대로(기간끼리만 차단,
     기간 안의 SLOT_CHANGE는 허용, 같은 날 SLOT_CHANGE 중복은 차단). 목록은 최근 7일 지난 것까지
     내려주고 `past=true`로 표시.
6. **예외 일정 삭제 API** — 삭제 후 materialize 재계산 (수정 API는 결정 2에 따라 안 만듦)
   - ✅ **8/18 완료.** `DELETE /exception/{id}`. `_del` 스냅샷 후 삭제 → 재계산 순서(뒤바뀌면 지운
     예외가 그대로 반영된다). 지난 예외는 삭제 불가.
7. **프론트 실연동** — `operation-schedule.js`를 실제 API 호출로 교체
   - ✅ **8/18 완료.** 조회/저장/예외등록/예외삭제 4개 연동. HTML의 목업 데이터(예외 2건, 요일 탭
     운영여부, 날짜 기본값) 제거. **저장은 사용자가 실제로 건드린 요일만 보낸다** — 7개를 항상 보내면
     예약이 걸린 요일 하나 때문에 나머지 6개까지 거부되기 때문(서버는 부분 전송을 그대로 받는다).
     회차 변경 예외는 왼쪽 표를 원본과 비교해 지시를 만든다(행 삭제=마감, 인원 변경=정원).
8. **통합 확인** — 저장 → 슬롯 생성 → 예외 적용 → 학생 예약 화면까지 이어지는지 점검
   - ⚠️ **부분 확인.** 요일 저장 → slot_instance 생성까지는 실제 데이터로 확인됨(8/18, 9/15까지 7회차).
     예외 등록·삭제, 예정 버전 삭제, 기간 예외는 아직 눈으로 확인 안 됨. 학생 예약 화면은 존재하지 않음.

**8/18 추가 작업 (계획에 없던 것)**

- **편집 모드** — 헤더의 편집 토글. 끄면 화면 전체가 읽기 전용이고 저장도 잠긴다. 보기 모드는
  "이번 주 그 요일의 실제 모습"(예외 적용)을, 편집 모드는 평소 요일 규칙을 보여준다. 예외가 적용된
  값이 요일 규칙으로 저장되는 사고를 구조적으로 막는다.
- **스케줄 변경 예약 이력 패널** — 요일 규칙 버전(이전/운영중/예정)과 특정일 예외를 한 타임라인에
  합쳐 보여준다. 종료일은 다음 버전 시작일 -1일로 계산하는 파생값이고, 요일 구성은 "그 시점의 주간
  전체"다. 예정 버전 삭제 API 추가(`DELETE /version/{effectiveFrom}`).
- **TIME_CHANGE 시 회차 직접 확정** — 운영시간을 바꾸면 회차도 함께 등록한다. 템플릿에서 걸러내는
  방식으로는 시간을 늘리거나 옮길 때 만들 회차가 없어서다. **DB 변경 1건**:
  `erp_bookstore_schedule_exception_slot`에 `start_time`/`end_time` 추가
  (`db/patch-schedule_exception_slot-time.sql` — 기존 DB는 이걸 실행해야 한다. 운영 DB 미적용).
- **이탈 방지** — 저장 안 한 변경이 있으면 뒤로가기·새로고침 시 경고.

**9. 일일 배치 (계획에 없었으나 추가)** — ✅ **8/18 완료.** `ScheduleMaterializeJob`, 매일 03:10 KST.
   없으면 예약 오픈 지평이 안 굴러가서 28일 뒤 예약 가능일이 0이 된다(화면상으론 멀쩡해 보이는 사고).
   멱등하므로 매일 지평 전체를 다시 찍는다 — 서버가 꺼져 있던 날의 구멍까지 메우기 위해.

일정 배정: 8/14(금) 1·2 / 8/15(토) 3·4 / 8/17(월) 5·6·7·8 — 실제로는 8/18(화)에 3~7 + 배치를 몰아서 완료.
