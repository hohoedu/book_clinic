## 1. 프로젝트 개요

호호책방 독서 클리닉 — 센터(학원) 학생에게 권장도서를 자동 추천하고, 독서 후 문제풀이/채점을 거쳐
EXP·레벨·뱃지로 보상하는 시스템.

| 구성 | 기술 |
|---|---|
| 서버 | Spring Boot (Java), Thymeleaf SSR + fetch 기반 JS |
| DB | MS SQL Server (Docker, `book_clinic_db`) |
| 프런트 | 정적 JS/CSS + PWA(서비스워커, 오프라인 폴백) |
| 단말 | **PWA — 웹페이지에서 홈 화면 설치 방식으로 확정** (스토어 게시 안 함. 별도 저장소의 Android 키오스크 앱은 미사용) |
| 푸시 | FCM (`FcmService`, `/api/notification`) |

## 2. 기능 정리

### 2-0. 전체 기능 맵 (사이드바 메뉴 기준)

관리자 사이드바(`fragments/sidebar.html`)에 계획된 전체 메뉴. 대분류 4개 / 화면 11개 중 2개 구현, 9개 미착수.

> **범위 확정 (2026-07-14): 11개 화면 전부 9/30 오픈 필수.** 미착수 9개 화면의 세부 기능은 아직 미확정.
> 기능 정의/화면 설계는 개발 작업 범위 외(별도 진행) — 확정되는 대로 이 문서의 2-x 섹션과 간트에 반영한다.

| 대분류 | 화면 | 상태 | 비고 (백엔드 준비 상태) |
|---|---|---|---|
| 데이터 관리 | 도서 데이터 관리 (`/admin/book-data`) | ✅ 완료 | |
| 데이터 관리 | 권장도서 순위 (`/admin/book-priority`) | ✅ 완료 | |
| 데이터 관리 | 레벨/뱃지 관리 | ❌ 미착수 | 테이블은 있음(level/exp_rule/badge, 현재 SQL 시드로만 관리) — 관리 API·화면 없음 |
| 운영관리 | 운영 현황 | ❌ 미착수 | 화면 성격(대시보드 범위) 정의 필요 |
| 운영관리 | 기관 관리 | ❌ 미착수 | erp_center 테이블만 있음(수동 시드) — CRUD API·화면 없음 |
| 운영관리 | 선생님 관리 | ❌ 미착수 | user 테이블·인증은 있음 — 계정 관리 API·화면 없음 |
| 모니터링 | 독서 모니터링 | ❌ 미착수 | 대여(item_loan)/추천(recommend_log) 데이터는 쌓이고 있음 |
| 모니터링 | 학생 진행 현황 | ❌ 미착수 | student_info(레벨/EXP), recommend_log 데이터 있음 — 조회 API·화면 없음 |
| 모니터링 | 결과 관리 | ❌ 미착수 | recommend_log에 점수/등급/완료일 저장됨 — 조회 API·화면 없음 |
| 성장관리 | 성장 리포트 | ❌ 미착수 | 학부모 앱과 콘텐츠 겹칠 가능성 — 범위 함께 정의 권장 |
| 성장관리 | 리워드 관리 | ❌ 미착수 | 기능 정의 자체가 없음 (뱃지와의 관계 정리 필요) |

**사이드바 외 영역**

| 영역 | 상태 | 비고 |
|---|---|---|
| 학생 PWA (로그인/메인/문제풀이/결과) | ✅ 로직 완료 | HTML/디자인 마무리만 남음 |
| 학부모 앱 (Flutter) | ❌ 미착수 | 범위/기능 정의부터 |
| 공통 코드 관리 (`/code/*`) | ⚠️ API만 | 관리 화면 없음 (필요 여부 결정) |
| FCM 푸시 알림 (`/api/notification/*`) | ⚠️ API만 | 발송/이력 UI 없음 — 어느 메뉴에 둘지 미정 (운영관리 후보) |

### 2-1. 관리자 — 도서 데이터 관리 (`/admin/book-data`) ✅ 구현 완료

- 도서 목록 / 도서 정보 / 문제 출제 3패널 단일 화면, 본사(PUS001)·비본사 권한 분기
- 마스터 도서 CRUD + 삭제 도서함(복구), 이미지 업로드 (`/book/*`, `/book/image`)
- 비본사 전용: 센터 하위(실물) 도서 CRUD, 재고 현황(보유/대여중/대여가능), 앱ID 대여·반납 (`/book/item/*`)
- 문제 출제: 기본(01)/심화(02) 탭, 학년·레벨별 고정 슬롯(기본 12/15문항, 심화 0/10/12문항),
  Summernote 지문 에디터, 엑셀 템플릿 업로드 (`/question/*`)
- 필수값 검증, 미저장 이탈 경고, 권한별 disabled 처리

### 2-2. 관리자 — 도서 추천 우선순위 관리 (`/admin/book-priority`) ✅ 구현 완료

- 학년 7개 탭(초1~중등), 드래그앤드롭 순위 편집(FLIP 애니메이션)
- 초안(draft) 시스템: 이번년도 즉시 적용 / 내년 예약 등록, 초안 목록·미리보기·적용·삭제 (`/priority/*`)
- 학년 7개 시트 일괄 엑셀 다운로드 (`/priority/excel`)

### 2-3. 학생 — 로그인 (`/student/login`) ✅ 구현 완료

- appId 텍스트 입력 (QR 스캔 임시 대체), 서버 폼 제출, 실패 flash 메시지
- PWA 등록(sw.js), 화면 확대/축소 차단

### 2-4. 학생 — 메인 (`/student/main`) ✅ 구현 완료 (HTML 다듬기 남음)

- 진입 시 자동 추천 `POST /clinic/recommend` — 멱등(미완료 추천 있으면 그대로 반환)
- 추천 규칙: 우선순위(sort_order) → 소속 센터 재고 필터 → 직전 도서와 분류+장르 동일 시 제외(dedup)
  → 후보 없으면 dedup 해제 재시도 → 그래도 없으면 상위 학년으로 순차 확장, 선택 즉시 대여 확정
- 추천 카드(표지/저자/요약/분류·장르/수상·교과·추천기관/키워드), "문제 풀기" 버튼
- 레벨 카드: 레벨 1~30 (1~10 입문 / 11~20 성장 / 21~30 마스터), required_exp 80~5760,
  학년별 권당 EXP(erp_bookstore_exp_rule) 기준 "다음 레벨까지 N권" + 진행률 바 — 실데이터 연동 완료
- 뱃지 패널(최대 4개, 카테고리 아이콘) / 이번 달 읽은 책(최대 4칸) — 테이블·서비스 로직 구현됨
  (`erp_bookstore_badge`/`student_badge`, `getEarnedBadges`/`getMonthBooks`)

### 2-5. 학생 — 문제풀이/결과 (`/student/question`, `/student/result`) ✅ 구현 완료 (심화는 부분)

- 문항 조회 → 풀이(4지선다, 이전/다음, 진행 도트) → 제출 `POST /clinic/quiz/submit`
- **서버 채점**: 클라이언트는 문항별 선택값만 전송, 서버가 itempool 정답과 대조 (조작 차단 검증 완료)
- 등급: 합격선 = ceil(문항수×2/3) — 만점=독서왕(KING) / 합격=독서친구(FRIEND) / 미달=재도전
- 합격 시 recommend_log DONE + EXP 지급 + 레벨업 판정 + 뱃지 재계산, 재도전은 PENDING 유지(같은 책 유지)
- 이미 완독한 책 재제출 시 EXP 재지급 없음(alreadyCompleted)
- 심화문제(qlevel=02): 화면 분기·빈 상태 처리는 동작, 단 **서버 기록/EXP 없음 + 시드 데이터 없음**

### 2-6. 공통/인프라 ✅ 구현 완료

- 공통 코드 관리 (`/code/*`), FCM 푸시 알림 발송·이력 (`/api/notification/*`)
- 이미지 업로드/저장 (`ImageStorageService`), 전역 예외 처리(400~500), Spring Security + 커스텀 인증
- PWA 캐싱 전략: 정적 리소스 프리캐시, `/js/` `/css/`는 network-first(구버전 캐시 버그 수정됨), API 캐시 안 함
- DB 시딩: content/item/itempool/center는 리셋 제외(수동 실행), 나머지는 매 기동 리셋

### 2-7. 단말 배포 — PWA 설치 방식 (확정)

- 웹페이지 접속 → PWA 설치(홈 화면 추가)로 배포. 관리자/학생 화면 모두 PWA 설치 버튼·매니페스트·서비스워커 구비
- 스토어 앱은 만들지 않음 — 별도 저장소의 Android 키오스크 앱(`book_clinic_kiosk_app`)은 초기 검토용으로, 사용하지 않기로 확정
